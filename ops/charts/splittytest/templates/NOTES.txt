Splitty Test {{ .Chart.AppVersion }} is installed as release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".

{{- if .Values.migrator.enabled }}

Database migrations run in the Job "{{ include "splittytest.fullname" . }}-migrate". Follow them with:
  kubectl --namespace {{ .Release.Namespace }} logs -f job/{{ include "splittytest.fullname" . }}-migrate
{{- end }}

1. Open the app:
{{- if .Values.httpRoute.enabled }}
  {{ include "splittytest.appUrl" . }}
{{- else if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
  {{- range .paths }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}{{ .path }}
  {{- end }}
{{- end }}
{{- else if contains "NodePort" .Values.service.type }}
  export NODE_PORT=$(kubectl get --namespace {{ .Release.Namespace }} -o jsonpath="{.spec.ports[0].nodePort}" services {{ include "splittytest.fullname" . }})
  export NODE_IP=$(kubectl get nodes --namespace {{ .Release.Namespace }} -o jsonpath="{.items[0].status.addresses[0].address}")
  echo http://$NODE_IP:$NODE_PORT
{{- else if contains "LoadBalancer" .Values.service.type }}
  It may take a few minutes for the LoadBalancer IP to be available.
  export SERVICE_IP=$(kubectl get svc --namespace {{ .Release.Namespace }} {{ include "splittytest.fullname" . }} --template "{{"{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}"}}")
  echo http://$SERVICE_IP:{{ .Values.service.port }}
{{- else }}
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "splittytest.fullname" . }} {{ .Values.app.port }}:{{ .Values.service.port }}
  Then visit http://localhost:{{ .Values.app.port }}
{{- end }}

2. Sign in with the first admin user{{ if not .Values.migrator.initUser }}: admin@splittytest.com / password{{ else }} from migrator.initUser{{ end }}
   Change the password right after signing in.

{{- if and (eq .Values.app.nodeEnv "production") (not .Values.ingress.tls) (not .Values.httpRoute.enabled) }}

WARNING: app.nodeEnv is "production", which only sends session cookies over HTTPS,
but no TLS is configured on the Ingress. Signing in over plain HTTP (including
port-forward) will fail. Add ingress.tls, terminate TLS elsewhere, or set
app.nodeEnv="" for testing.
{{- end }}

{{- if not .Values.mailgun.apiKey }}

NOTE: Mailgun isn't configured (mailgun.apiKey / mailgun.domain), so emails such as
password resets won't be sent.
{{- end }}
